This repository is an accumulation of junk scripts I made for the Skinner lab, tackling the problem of whether the price of anarchy (POA) is maximized at the percolation threshold of the Barabasi-Albert Model. For anyone who wants to read the code here, beware: none of it is explained, documented, and you will often be misled because I did not follow best practices. This is not an example for that, regrettably, but I did follow better practices in the Furnstahl group repo, so have a look there if you want something coherent. Also, there are some graphs that have titles that are hardcoded rather than using variables and this can cause two identically named and labelled graphs to show opposite behavior so... if you want to know for sure, you oughta run it yourself. 

To set the stage somewhat, the idea is that we think of whatever graph we have in mind as a set of roads connected by the nodes. Then, we imagine that we "cut" each road at some severance probability, p. The percolation threshold is defined (here, convention could be 1-p as well) as the highest value of p, p_c, such that the graph still has long-term connectivity. That's not a very rigorous definition, but this is enough to understand the idea behind the problem. 

The price of anarchy is basically just the ratio between the social equilibrium and the social optimum for global commute time, which is obviously above or equal to 1 always.

Now, instead of thinking of "cutting" edges, we think of assigning a certain cost function. In particular, we assign "slow roads" (constant cost function) and "fast roads" (cost proportional to traffic), and we can in fact find both the optimum and equilibrium for a certain choice of p with a simple application of quadratic programming. I think basically every script does this, but the "recreate" scripts will be more pedagogical (though... lacking in explanation because I was still in my phase of never documenting anything). They basically recreate the curves from Dr. Skinner's original paper on the topic for a diamond lattice. 

Now, the diamond lattice works out great, but as you'll see the BA model won't work out so nicely. The BA model is what you'd call a scale-free network, so its depth never really increases all that much even if you add a bunch of nodes. You'll find this... somewhere in miscellaneous_scripts I think. This should be rather intuitively clear if you understand that the BA model is a "rich get richer" model, and we're particularly starting from one node at the center. I actually tried starting with a different graph before performing the algorithm to form the graph, but this was causing problems, particularly with designating "start" and "end" nodes. So I elected to keep it simple, have one ending node be at the center and start from all the outermost nodes. 

Okay now we have enough background to state the problem. Is the price of anarchy maximized for the BA model if we set p_c*100% of its roads to fast roads (as opposed to using some other p)?

Intuitively, we expect this to be the case for something like the diamond lattice for the following reason. The value p_c is the point at which one long line will form across the graph. When this line forms, everybody will try to abuse this one line. Before this probability, there won't be as much to abuse so selfish decisions won't affect much. After this probability, a lot of fast roads will be available across the graph, so selfish decisions won't hog up traffic as much. For the diamond lattice p_c ~ 0.6 or something. 

The first predictable problem with the BA model is that it has p_c = 0 or 1, depending on a parameter "m" which is unimportant to what I want to discuss here. We want to see peaks at the percolation threshold, but at p = 0 or 1, the POA is, by definition 1. This presents a profound problem. We figured that perhaps we might just want to see peaks that move closer and closer to 0 or 1 for the associated value of "m". Things looked somewhat promising for m=2, which should have a peak near 0, but then I noticed the same thing was happening for m=1, which should have a peak near 1. Intuitively we figured the problem was that there were just way too many ways to go from the start nodes to the end nodes that we couldn't possibly hope for a nontrivial POA when we start setting a significant amount of roads to "fast roads". The lack of complicated paths from start to finish was another potential problem, they were largely exceedingly short after all (because in the rich get richer scheme, everybody just directly connects to the most connected guy, which is usually the guy in the middle aka our end node). 

One of the ways I figured we could fight this was to pick only the longest paths. And actually this works pretty well, we get the expected results. But ultimately we rejected this, because once we start discarding paths we're in the business of making our own model and that defeats the purpose of what we set out to do. So, this just ended up going on the paper after further research with nonlinear cost functions (not done by me, done by the grad student who was working with me, and that's not in this repo). 

There's more discussion on this in the paper: https://arxiv.org/abs/2503.09684   (section VI. B)
